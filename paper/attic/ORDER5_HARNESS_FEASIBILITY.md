# Order-5 Lean harness: feasibility finding (2026-07-01)

PAPER_PLAN.md's risk section flags: "Lean harness for arbitrary order-5 laws
is heavy infra — budget it; the ETP generated defs/checkers were built for
the 4694 order-≤4 laws." This session set up a real Lean toolchain and
tested that claim directly. **Result: it's not heavy infra — the existing
judge already works, unmodified, on arbitrary order-5 equation pairs.**

## What was set up
- Installed elan + Lean 4.30.0-rc2 (the exact version pinned in
  `lean-toolchain`) in the Cowork sandbox via direct binary download
  (elan's own downloader kept getting cut off by the 45s bash cap on a
  505MB file; worked around it with a resumable `curl -C -` fetch + manual
  extraction into elan's toolchain directory).
- **Disk was tight** (single-digit GB free across the sandbox's two
  filesystems) and the toolchain alone is ~2.7GB. Mathlib (declared as a
  dependency in `lakefile.lean`) would have needed several GB more —
  probably not fitting.
- **Grepped every judge/submission Lean source for `import Mathlib`: zero
  matches outside `reference/`** (the separate, already-resolved ETP repo).
  `judge/JudgeMagma/Magma.lean`, `JudgeDecide/DecideBang.lean`,
  `JudgeFinOp/MemoFinOp.lean`, `JudgeSupport/Inspect.lean`, and the
  per-problem generated `JudgeProblem.lean` all import only core `Lean`.
  Mathlib is declared but **unused** by the actual judge/checker code.
- Mirrored the project into a scratch directory with the `require mathlib`
  line stripped from `lakefile.lean`, then `lake build` succeeded in
  seconds with zero mathlib fetch, zero extra disk.

## The actual test
Took `judge/verify.py`'s real `verify_answer()` function (unmodified) and
fed it genuine order-5 pairs from `paper/problems/order5_probe.jsonl`
(eq1_id/eq2_id > 4694, outside the published order-≤4 graph):
- **FALSE side**: `order5v2_0001`, countermodel found by
  `scripts/my_solver_merged/solver.py`'s own `search_counterexample` (Fin 2),
  cert generated by the same `make_false_code` used in production →
  **judge accepted**.
- **TRUE side**: `order5_0222`, proof found by the same solver's
  `try_direct_h_application` stage → **judge accepted**.
- Ran the packaged smoke-test script (`paper/scripts/order5_harness_smoketest.py`)
  on 5 more order-5 pairs → **5/5 accepted**.
- 7/7 across both manual and scripted tests.

## One gotcha, resolved
First attempt got rejected with `DISALLOWED_AXIOMS` (propext, Quot.sound,
Classical.choice). This is **not** a real problem — `verify.py`'s default
`ProofPolicy` (when a problem dict omits `proof_policy`) rejects every
axiom, and the raw problem jsonl files never carry that field. The real
system attaches `pipeline/proxy.py::DEFAULT_PROOF_POLICY` (which allows
those three ubiquitous, harmless Lean4-std axioms plus a declaration
allowlist) before calling `verify_answer`. Once the same policy is attached
in the standalone test, everything works. `docs/SOLVER_STATUS.md` §0.2
already documents this policy and its declaration allowlist (that's how
`hard2_0051`'s real infra limits were discovered).

## What this means for PAPER_PLAN step 3
The "order-5 Lean harness" isn't a build project — it's a **usage** of
existing infrastructure. What's actually needed to run C1–C4 for real:
1. A driver that reads order-5 pairs (already have
   `paper/scripts/sample_order5.py` / `cheap_false_screen.py`), and for
   each, calls `verify_answer` (with `DEFAULT_PROOF_POLICY` attached) on
   solver-produced or LLM-proposed certs — this is now proven to work.
2. `paper/scripts/order5_harness_smoketest.py` is a reusable reference
   implementation of the correct call pattern (proof_policy attached,
   mathlib-free setup documented) for whoever builds that driver next.
3. The mathlib-free sandbox setup (elan + stripped lakefile) means this can
   keep being tested cheaply in Cowork sessions, not just on your real
   machine — worth keeping `/tmp/leanhome` conventions if this environment
   persists, though toolchains don't survive across sessions so this setup
   would need to be redone next time unless persisted somewhere.

## Caveat
This validates the **mechanism** (judge accepts order-5 pairs same as
order-≤4). It does not by itself validate that the deterministic portfolio
(`STEELMAN_PORTFOLIO.md`) or an LLM proposer will find enough order-5
witnesses to run a full C1–C4 study — that's still open work, now unblocked
rather than blocked on infra.
